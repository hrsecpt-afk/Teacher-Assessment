# ระบบประเมินผลการปฏิบัติงาน
### ศูนย์การศึกษาพิเศษ ประจำจังหวัดปทุมธานี

ระบบเว็บสำหรับประเมินผลการปฏิบัติงานบุคลากรทุกตำแหน่ง แยกหน้าจอผู้รับการประเมิน / คณะกรรมการ / ผู้ดูแลระบบ
และพิมพ์ออกเป็น PDF ตามแบบฟอร์มราชการจริงของแต่ละตำแหน่ง

---

## เริ่มใช้งาน

เปิดไฟล์ `index.html` ด้วย Chrome / Edge ได้ทันที (ไม่ต้องติดตั้งอะไร)

### วิธีเข้าสู่ระบบ

| บทบาท | วิธีเข้า |
|---|---|
| **ผู้รับการประเมิน** | เลือกชื่อตนเองจากรายการ (พิมพ์ค้นหาได้) → ใส่รหัสผ่าน |
| **กรรมการประเมิน** | เลือกชื่อตนเองจากรายการ → ใส่รหัสผ่าน |
| **ผู้ดูแลระบบ** | ชื่อผู้ใช้ + รหัสผ่าน (เริ่มต้น `admin` / `admin1234`) |

ผู้ใช้ทั่วไปไม่ต้องจำชื่อผู้ใช้ จำแค่รหัสผ่านของตนเอง
รายชื่อในเมนูจัดกลุ่มตามตำแหน่งและดึงจาก Google Sheets อัตโนมัติ

> เครื่องที่เพิ่งเปิดใช้ครั้งแรกจะยังไม่มีรายชื่อ ต้องให้ผู้ดูแลระบบเข้าที่แท็บ *ผู้ดูแลระบบ*
> แล้วตั้งค่าเชื่อมต่อ Google Sheets ก่อน รายชื่อจึงจะขึ้นมาให้เลือก

### ลำดับการตั้งค่าครั้งแรก

1. เข้าสู่ระบบเป็น **ผู้ดูแลระบบ**
2. *ตั้งค่าระบบ* → **เชื่อมต่อ Google Sheets ก่อนเป็นอันดับแรก** (ดูหัวข้อ *การเก็บข้อมูล* ด้านล่าง)
   ถ้ายังไม่เชื่อม ข้อมูลจะอยู่แค่ในเบราว์เซอร์เครื่องนั้น
3. *ตั้งค่าระบบ* → ตรวจชื่อหน่วยงาน ชื่อผู้อำนวยการ และปีงบประมาณ
4. *คณะกรรมการประเมิน* → เพิ่มรายชื่อกรรมการ พร้อมชื่อผู้ใช้/รหัสผ่าน
5. *ผู้รับการประเมิน* → เพิ่มบุคลากร เลือกตำแหน่ง พร้อมชื่อผู้ใช้/รหัสผ่าน
6. *รอบการประเมิน* → เลือก บุคคล + แบบประเมิน + ปีงบประมาณ/รอบ + กรรมการ (เลือกได้หลายคน)
7. แจ้งชื่อผู้ใช้/รหัสผ่านให้เจ้าตัวและกรรมการ

## บทบาทและสิ่งที่ทำได้

| บทบาท | ทำอะไรได้ |
|---|---|
| **ผู้รับการประเมิน** | กรอกข้อมูลส่วนตัวและสถิติวันลา · อัปโหลดเล่มรายงาน/ไฟล์นำเสนอ · ดูผลการประเมินและพิมพ์ PDF ของตนเอง |
| **กรรมการประเมิน** | เห็นเฉพาะคนที่ตนรับผิดชอบ · เปิดเอกสารแนบประกอบการพิจารณา · ให้คะแนน (บันทึกร่างได้) · เขียนจุดเด่น/จุดที่ควรพัฒนา/ข้อคิดเห็น · พิมพ์แบบประเมินของตน |
| **ผู้ดูแลระบบ** | จัดการบุคลากร กรรมการ รอบการประเมิน · ดูแดชบอร์ดและผลรวม · **แก้ไข/ลบผลคะแนนแทนกรรมการได้** · พิมพ์เอกสารทุกฉบับ · สำรอง/กู้คืนข้อมูล |

### ผู้ดูแลระบบแก้ผลการประเมิน

ใช้ตอนทดลองใช้ระบบ หรือแก้ให้เมื่อกรรมการกรอกผิดแล้วแจ้งมา

*ผลการประเมิน* → ปุ่ม **จัดการผล** ที่แถวนั้น → เห็นสถานะและคะแนนของกรรมการทุกคน
เลือก **แก้ไขคะแนน** (กรอกในนามกรรมการท่านนั้น) หรือ **ลบผล**

ในหน้าให้คะแนนจะมีแถบสีเหลือง *โหมดผู้ดูแลระบบ* บอกว่ากำลังกรอกในนามใคร และสลับกรรมการได้จากดรอปดาวน์

เมื่อทดลองเสร็จ ล้างข้อมูลทดลองได้ที่ *ตั้งค่าระบบ → ข้อมูลทดลองใช้ระบบ → **ล้างผลการประเมินทั้งหมด***
ซึ่งลบเฉพาะคะแนนและข้อสังเกต — รายชื่อบุคลากร คณะกรรมการ และรอบการประเมินยังอยู่ครบ

**กรรมการหลายคนให้คะแนนแยกกัน** ระบบเก็บคะแนนของแต่ละคนไว้คนละชุด แล้วออก
*ใบสรุปผลการประเมินของคณะกรรมการ* ที่แสดงคะแนนรายคนและค่าเฉลี่ย

## แบบประเมินที่รองรับ (9 แบบ / 7 ตำแหน่ง)

| ตำแหน่ง | แบบประเมิน | โครงสร้างคะแนน |
|---|---|---|
| ครูผู้ช่วย | เลื่อนเงินเดือน | อค.1 (14 ตัวชี้วัด ×80÷56 = 80) + อค.2 (10) + อค.3 (10) = **100** |
| ครู (ยังไม่มีวิทยฐานะ) | PA2/ส | ส่วนที่ 1 (60) + ส่วนที่ 2 (40) = **100** |
| ครู (ยังไม่มีวิทยฐานะ) | เลื่อนเงินเดือน | อค.1 = ตอน 1 (60) + ตอน 2 (raw 40 ×20÷40 = 20) → 80 · +อค.2 (10) +อค.3 (10) = **100** |
| ครู วิทยฐานะครูชำนาญการ | PA2/ส | เหมือนข้างบน แต่ระดับที่คาดหวัง = *แก้ไขปัญหา* และมีเกณฑ์ผ่านรายกรรมการ ≥ 70% |
| ครู วิทยฐานะครูชำนาญการ | เลื่อนเงินเดือน | เหมือนครูยังไม่มีวิทยฐานะ (ถ้อยคำตัวชี้วัดยกระดับขึ้น) |
| พนักงานราชการ | ผลสัมฤทธิ์ + สมรรถนะ | ผลสัมฤทธิ์ 7 ตัวชี้วัด (น้ำหนัก 80%) + สมรรถนะ 7 ด้าน 37 ข้อ (20%) = **100** |
| ครูอัตราจ้าง | ผู้ปฏิบัติงานให้ราชการ | 5 หมวด 18 รายการ = **200** → คิดเป็นร้อยละ |
| ครูธุรการ | ผู้ปฏิบัติงานให้ราชการ | 2 องค์ประกอบ × 10 รายการ × 10 = **200** → ร้อยละ (ผ่าน ≥ 75) |
| จ้างเหมาบริการ | พี่เลี้ยงเด็กพิการ/ภารโรง/ยาม ฯลฯ | 10 รายการ × 10 = **100** + เกณฑ์พิจารณาต่อสัญญา 3 ระดับ |

ระบบคำนวณคะแนนดิบ → แปลงตามสูตรของแต่ละแบบฟอร์ม → ตัดเกรดตามเกณฑ์ของฟอร์มนั้นโดยอัตโนมัติ

## การพิมพ์ PDF

หน้า *พิมพ์แบบประเมิน* มี 3 โหมด

- **แบบเต็ม** — แบบประเมินของกรรมการทุกคน + ใบสรุปคณะกรรมการ
- **เฉพาะใบสรุปผล** — หน้าเดียว เหมาะสำหรับแนบเสนอ
- **แบบฟอร์มเปล่า** — พิมพ์ไว้กรอกด้วยมือ

กด **พิมพ์ / บันทึกเป็น PDF** แล้วในกล่องพิมพ์ของเบราว์เซอร์ตั้งค่า

| ตัวเลือก | ค่าที่ควรใช้ |
|---|---|
| ปลายทาง (Destination) | บันทึกเป็น PDF |
| ขนาดกระดาษ | A4 |
| ระยะขอบ (Margins) | **ไม่มี / None** — ระยะขอบราชการถูกกำหนดในตัวเอกสารแล้ว |
| กราฟิกพื้นหลัง | **เปิด** — เพื่อให้หัวตารางมีพื้นสีเทาเหมือนต้นฉบับ |

## การเก็บข้อมูล — Google Sheets + Google Drive

สคริปต์จะสร้างสเปรดชีตฐานข้อมูลและโฟลเดอร์เก็บไฟล์แนบให้เองในไดรฟ์ของบัญชีที่ติดตั้ง
ไม่ต้องเตรียมไฟล์ล่วงหน้า และไม่ต้องแก้โค้ด

> ถ้าต้องการใช้สเปรดชีตที่มีอยู่แล้ว ให้ใส่รหัสชีตในตัวแปร `SHEET_ID` บรรทัดบนสุดของ `Code.gs`
> แล้วข้ามขั้นตอนที่ 3 ไป — บัญชีที่ติดตั้งต้องมีสิทธิ์ *ผู้แก้ไข* ในชีตนั้น

### ติดตั้งครั้งเดียว

> ทำในหน้าต่าง Chrome แบบ **ไม่ระบุตัวตน** (`Ctrl+Shift+N`) แล้วล็อกอินบัญชีที่ต้องการติดตั้ง
> ถ้าล็อกอินหลายบัญชีพร้อมกัน Apps Script มักไปสร้างโปรเจกต์ผิดบัญชีโดยไม่รู้ตัว

1. เปิด <https://script.google.com> → **New project** → ตั้งชื่อโปรเจกต์
2. ลบโค้ดใน `Code.gs` ทิ้ง แล้ววางเนื้อหาไฟล์ **`google_apps_script/Code.gs`** ลงไป → บันทึก (`Ctrl+S`)
3. เลือกฟังก์ชัน **`createNewSpreadsheet`** ในแถบด้านบน → กด **Run**
   ครั้งแรกจะเจอหน้าขออนุญาตสิทธิ์ ให้ทำตามหัวข้อ *ด่านขออนุญาตสิทธิ์* ด้านล่าง
   → Execution log จะแสดงลิงก์สเปรดชีตที่สร้างให้
4. เลือกฟังก์ชัน **`setupFirstTime`** → กด **Run**
   → Execution log ต้องแสดงรายชื่อชีตที่สร้าง และลิงก์โฟลเดอร์ไฟล์แนบ
5. *(แนะนำ)* ตั้งรหัสลับกันคนอื่นเรียก API — **Project Settings → Script Properties → Add**
   property ชื่อ `API_KEY` ค่าอะไรก็ได้ที่เดายาก
6. กด **Deploy → New deployment** → ⚙ → เลือกประเภท **Web app**
   - Execute as → **Me**
   - Who has access → **Anyone**
7. คัดลอก **Web app URL** ที่ลงท้ายด้วย `/exec`
8. เปิดระบบ → เข้าเป็นผู้ดูแล → *ตั้งค่าระบบ* → วาง URL (และ `API_KEY` ถ้าตั้งไว้) → **บันทึกและทดสอบการเชื่อมต่อ**
9. ถ้ามีข้อมูลที่กรอกไว้ในเครื่องแล้ว กด **ส่งข้อมูลในเครื่องขึ้น Google Sheets** หนึ่งครั้ง

> ต้องทำขั้นตอน 1–6 **ครั้งเดียว** เท่านั้น เครื่องอื่น ๆ แค่วาง URL เดิมในหน้าตั้งค่าระบบก็ใช้ข้อมูลชุดเดียวกันได้เลย

### ชีตที่ระบบสร้าง

| ชีต | เก็บอะไร |
|---|---|
| `people` | ทะเบียนผู้รับการประเมิน + บัญชีเข้าใช้ |
| `evaluators` | รายชื่อคณะกรรมการ + บัญชีเข้าใช้ |
| `assignments` | รอบการประเมิน (ใคร / แบบไหน / ปี-รอบ / กรรมการคนใด) |
| `evaluations` | คะแนนของกรรมการแต่ละคน พร้อมคอลัมน์ `total` `percent` `grade` ที่คำนวณแล้ว |
| `leaveRecords` | สถิติวันลา แยกคอลัมน์ตามประเภท × รอบ |
| `attachments` | รายการไฟล์แนบ พร้อมลิงก์ Google Drive |
| `settings` | ค่าตั้งค่าของหน่วยงาน |

คะแนนรายข้อเก็บเป็น JSON ในคอลัมน์ `scores` (ข้อมูลชุดใหญ่และรูปแบบต่างกันตามแบบฟอร์ม)
แต่คอลัมน์สรุป `total` / `percent` / `grade` เป็นตัวเลขจริง จึงนำไปทำ Pivot หรือกราฟใน Sheets ได้ทันที

### ทำงานอย่างไร

ระบบทำงานกับสำเนาในเครื่องเสมอ แล้วส่งขึ้น Google Sheets ทุกครั้งที่บันทึก
**เน็ตหลุดก็ยังกรอกคะแนนต่อได้** ข้อมูลจะค้างในเครื่องและมุมซ้ายล่างจะขึ้นเตือน
เมื่อกลับมาออนไลน์ให้กด *ตั้งค่าระบบ → ส่งข้อมูลในเครื่องขึ้น Google Sheets*

**สำรองข้อมูล** ที่ *ตั้งค่าระบบ → ดาวน์โหลดไฟล์สำรอง (.json)* ควรทำก่อนสิ้นรอบการประเมินทุกครั้ง

### ด่านขออนุญาตสิทธิ์ (เจอแน่ทุกคนตอนติดตั้งครั้งแรก)

Apps Script ที่เขียนเองจะไม่ผ่านการรับรองจาก Google จึงมีหน้าเตือนกั้นไว้ **ต้องดูหัวเรื่องให้ดี เพราะมี 2 แบบ**

**แบบที่ 1 — “Google hasn’t verified this app” / “ยังไม่ได้ยืนยันแอปนี้”** ← ผ่านได้เอง

```
Google hasn't verified this app
        ↓ กด  Advanced  (หรือ "ขั้นสูง")
        ↓ กด  Go to <ชื่อโปรเจกต์> (unsafe)   ← ต้องกดบรรทัดนี้ ตัวหนังสือเล็กมาก
        ↓ กด  Allow / อนุญาต
```

คำว่า *(unsafe)* คือคำเตือนมาตรฐานสำหรับสคริปต์ที่ไม่ได้ส่งให้ Google ตรวจ — สคริปต์นี้เป็นของเราเอง
และเข้าถึงเฉพาะสเปรดชีตกับโฟลเดอร์ไฟล์แนบของบัญชีตัวเองเท่านั้น

**แบบที่ 2 — “Access blocked” / “แอปนี้ถูกบล็อก”** ← ผ่านเองไม่ได้

เกิดกับบัญชี Google Workspace ของโรงเรียน/หน่วยงาน ที่ผู้ดูแลตั้งนโยบายห้ามใช้แอปที่ยังไม่ได้รับการรับรอง
มี 2 ทางแก้

| ทางเลือก | วิธีทำ |
|---|---|
| **ใช้บัญชี Gmail ส่วนตัวแทน** (เร็วที่สุด) | ดูขั้นตอนละเอียดหัวข้อถัดไป |
| **ให้ผู้ดูแลระบบขององค์กรอนุญาต** | Admin console → Security → Access and data control → **API controls** → Manage third-party app access → เพิ่มโปรเจกต์นี้เป็น *Trusted* |

### ย้ายไปติดตั้งบนบัญชี Gmail ส่วนตัว

ทำตามหัวข้อ *ติดตั้งครั้งเดียว* ด้านบนได้เลย โดยล็อกอินด้วย Gmail ส่วนตัว
ไม่ต้องแชร์สเปรดชีตของโรงเรียนออกมา เพราะขั้นตอนที่ 3 จะสร้างชีตใหม่ในไดรฟ์ของ Gmail นั้นให้เอง

ไฟล์แนบจะไปอยู่ใน Google Drive ของ Gmail ส่วนตัว โฟลเดอร์ *ไฟล์แนบระบบประเมินผลการปฏิบัติงาน*
ตั้งสิทธิ์ “ผู้ที่มีลิงก์เปิดดูได้” อัตโนมัติ กรรมการจึงเปิดจากบัญชีโรงเรียนได้ตามปกติ

> เคล็ดลับ: ก่อน Deploy ให้เลือกฟังก์ชัน **`setupFirstTime`** ในเมนู Run แล้วกดรันหนึ่งครั้งก่อน
> จะได้จบด่านขออนุญาตสิทธิ์ตั้งแต่ตอนนั้น และเห็นข้อความผิดพลาดชัดกว่าตอน Deploy มาก
> ถ้ารันผ่าน จะเห็นใน Execution log ว่าสร้างชีตครบและได้ลิงก์โฟลเดอร์ไฟล์แนบแล้ว

### แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| กด "ทดสอบการเชื่อมต่อ" แล้วขึ้นว่า *เซิร์ฟเวอร์ไม่ได้ตอบเป็น JSON* | Deploy ไม่ได้ตั้ง **Who has access = Anyone** (URL จะเด้งไปหน้า login ของ Google แทนที่จะตอบข้อมูล) — แก้แล้วต้องกด **Deploy → Manage deployments → ✏️ → Version: New version → Deploy** |
| ช่อง Who has access ไม่มีตัวเลือก **Anyone** | บัญชีองค์กรถูกนโยบายจำกัด — ใช้บัญชี Gmail ส่วนตัวแทน (ดูตารางในหัวข้อ *ด่านขออนุญาตสิทธิ์*) |
| เชื่อมต่อไม่ได้เมื่อเปิดไฟล์แบบ `file://` | เบราว์เซอร์บางรุ่นบล็อกคำขอข้ามโดเมนจากไฟล์ในเครื่อง ให้เปิดผ่านเว็บเซิร์ฟเวอร์แทน เช่นสั่ง `npx serve` ในโฟลเดอร์นี้ แล้วเปิด `http://localhost:3000` หรืออัปขึ้นโฮสต์ฟรีอย่าง GitHub Pages |
| แก้โค้ดใน Apps Script แล้วไม่มีผล | ต้อง **Deploy เวอร์ชันใหม่** ทุกครั้ง (URL เดิมจะยังชี้เวอร์ชันเก่า) |
| ขึ้นว่า *รหัสลับ (API key) ไม่ถูกต้อง* | ค่าในช่อง "รหัสลับ API" ไม่ตรงกับ Script Property ชื่อ `API_KEY` |
| มุมซ้ายล่างขึ้น ⚠ ตลอด | บันทึกขึ้นชีตไม่สำเร็จ ข้อมูลยังอยู่ครบในเครื่อง — เมื่อแก้การเชื่อมต่อแล้วให้กด *ส่งข้อมูลในเครื่องขึ้น Google Sheets* |

> Apps Script ต้องใช้ runtime **V8** (เป็นค่าเริ่มต้นของโปรเจกต์ใหม่อยู่แล้ว)

## โครงสร้างไฟล์

```
index.html                    โครงหน้าเว็บ + หน้าเข้าสู่ระบบ
css/app.css                   หน้าจอใช้งาน
css/print.css                 แบบฟอร์มพิมพ์ A4
js/config.js                  ข้อมูลหน่วยงาน ตำแหน่ง เกณฑ์ระดับผล รอบการประเมิน
js/forms.js                   นิยามแบบประเมินทั้ง 9 แบบ + เครื่องคิดคะแนน
js/store.js                   เก็บข้อมูล (ในเครื่อง + Google Sheets/Drive) + บัญชีผู้ใช้
js/print.js                   สร้างแบบฟอร์มราชการสำหรับพิมพ์
js/app.js                     เมนู เส้นทาง และทุกหน้าจอ
google_apps_script/Code.gs    ฝั่งเซิร์ฟเวอร์ — วางใน script.google.com
```

## ข้อควรทราบ

- **ความปลอดภัย** ระบบออกแบบสำหรับใช้ภายในหน่วยงาน รหัสผ่านผู้ใช้เก็บแบบง่าย ไม่ใช่การเข้ารหัสเชิงความปลอดภัย
  อย่าใช้รหัสผ่านเดียวกับบัญชีสำคัญอื่น
- **การเข้าระบบแบบเลือกชื่อ** ทำให้รายชื่อบุคลากรปรากฏก่อนล็อกอิน และรหัสผ่านกลายเป็นสิ่งเดียวที่กันคนอื่นเข้าแทนตัวเรา
  จึงไม่ควรใช้รหัสผ่านที่เดาได้จากชื่อผู้ใช้ ควรให้แต่ละคนเปลี่ยนรหัสผ่านของตนเอง
  (ผู้ดูแลระบบเปลี่ยนให้ได้ที่เมนู *ผู้รับการประเมิน* → แก้ไข → ช่องรหัสผ่าน)
  Web app ถูก Deploy แบบ *Anyone* เพื่อให้เรียกจากหน้าเว็บได้ — **ใครมี URL ก็เข้าถึงข้อมูลได้**
  จึงควรตั้ง `API_KEY` ตามขั้นตอนที่ 3 และไม่เผยแพร่ URL/รหัสลับสู่สาธารณะ
- **เกณฑ์ระดับผลของแบบเลื่อนเงินเดือน** ไฟล์ต้นฉบับ `.docx` ที่ได้รับมาพิมพ์ช่วงคะแนนคลาดเคลื่อน
  (ช่วงทับซ้อน/ขาดหาย เช่น *ดีมาก ๘๐.๐๐–๘๕.๔๔* และ *พอใช้ 50.00–๖๙.๙๙* คู่กับ *ปรับปรุง ๕๙.๙๙ ลงมา*)
  ระบบจึงใช้ช่วงมาตรฐานของ ก.ค.ศ. แทน คือ ดีเด่น ≥90 · ดีมาก 80–89.99 · ดี 70–79.99 · พอใช้ 60–69.99 · ต้องปรับปรุง <60
- **แบบครูธุรการ** ต้นฉบับระบุคำชี้แจงว่ามี 3 องค์ประกอบ 300 คะแนน แต่ตารางจริงมี 2 องค์ประกอบ 200 คะแนน
  และไม่ได้ใส่เกณฑ์ระดับผล (มีโน้ตค้างไว้ว่า *"ใส่เกณฑ์เหมือนครูอัตราจ้าง"*)
  ระบบจึงทำตามตารางจริง 200 คะแนน และใช้เกณฑ์เดียวกับครูอัตราจ้าง ตามที่โน้ตระบุ
  หากหน่วยงานเพิ่มองค์ประกอบที่ 3 ภายหลัง แก้ได้ที่ `js/forms.js` → `FORMS.admin_officer`
